## 3. 核心模块详细说明

### 3.1 M01 — 仓库管理模块

**功能描述**:
- 注册新仓库（验证 GitHub 存在性）
- 查询仓库列表与详情

**接口列表**:

| 方法 | 路径 | Handler | 说明 |
|------|------|---------|------|
| POST | /api/repos | `post_repos_handler` | 注册仓库 |
| GET | /api/repos | `get_repos_handler` | 仓库列表 |

**数据表**: `repos`

### 3.2 M02 — 数据同步模块

**功能描述**:
从 GitHub REST API 拉取仓库数据，支持全量与增量两种模式。同步内容包括仓库快照、Issues、Pull Requests、Commits 和 Releases。

**主要函数**:

```cpp
// github_client.h
nlohmann::json github_list_issues(Db& db, int repo_id, int page, int per_page, const std::string& state, const std::string& since);
nlohmann::json github_list_pulls(Db& db, int repo_id, int page, int per_page, const std::string& state, const std::string& since);
nlohmann::json github_list_commits(Db& db, int repo_id, int page, int per_page, const std::string& since);
nlohmann::json github_list_releases(Db& db, int repo_id, int page, int per_page);
nlohmann::json github_get_pull(Db& db, int repo_id, int pull_number);
nlohmann::json github_search_issues_prs(Db& db, int repo_id, const std::string& query);
nlohmann::json github_get_commit_files(Db& db, int repo_id, const std::string& sha);
nlohmann::json github_list_workflow_runs(Db& db, int repo_id, int page, const std::string& branch);
```

**增量同步机制**:
- 每次同步成功后推进游标（cursor）
- Issues: 基于 `updated_at` 游标
- PRs: 使用 Search API 查询 `updated:>=cursor`
- Commits: 基于 `committed_at` 游标
- Releases: 基于 `published_at` 游标

**数据表**: `repo_sync_state`, `repo_sync_runs`, `issues`, `pull_requests`, `commits`, `releases`

### 3.3 M05 — 知识库模块

**功能描述**:
从仓库已同步数据中提取知识块，构建 RAG 检索索引。支持混合检索策略（关键词 + 向量语义）。

**主要函数**:

```cpp
// knowledge_base.h
struct KnowledgeChunk {
    int id;
    int repo_id;
    std::string source_type;  // issue / pull_request / commit / release / code / expert / risk_alert
    std::string source_id;
    std::string title;
    std::string content;
    std::string author;
    std::string event_time;
    std::vector<float> embedding;  // 向量嵌入
};

struct BuildIndexResult {
    int issues_indexed;
    int pulls_indexed;
    int commits_indexed;
    int releases_indexed;
    int total_indexed;
    int embeddings_generated;
};

BuildIndexResult build_knowledge_index(Db& db, int repo_id);
nlohmann::json search_knowledge(Db& db, int repo_id, const std::string& query, int top_k);
nlohmann::json keyword_search(Db& db, int repo_id, const std::string& query, int top_k);
nlohmann::json vector_search(Db& db, int repo_id, const std::vector<float>& query_embedding, int top_k);
```

**混合检索算法**:
```
score = keyword_normalized_score * 0.4 + vector_similarity * 0.6
```
- 关键词检索: SQL `LIKE` 匹配 title/content/author/source_type/source_id
- 向量检索: 调用 Embedding API 生成查询向量，余弦相似度暴力搜索
- 降级: Embedding API 不可用时自动退回纯关键词检索

**数据表**: `knowledge_chunks`

### 3.4 M06 — AI 问答模块

**功能描述**:
基于 RAG 的工程智能问答。用户提问后，系统检索相关证据 → 获取当前指标 → 组装 Prompt → 调用 LLM → 返回带引用的回答。

**主要函数**:

```cpp
// ai_assistant.h
struct AiAnswer {
    std::string answer;
    std::vector<AiEvidence> evidence;
    std::string model;
    bool success;
    std::string error;
    int prompt_tokens;
    int completion_tokens;
    int total_tokens;
    double cost_usd;
    long long duration_ms;
};

AiAnswer ask_question(Db& db, int repo_id, const std::string& question);
AiAnswer call_llm(const std::string& system_prompt, const std::string& user_message);
```

**问答流程**:
```
用户提问 → 关键词提取 → 知识库检索(Top-10) → 获取当前指标 →
组装系统提示+指标上下文+检索证据+用户问题 → 调用 LLM API →
返回带引用的回答 → 保存对话记录 → 记录 AI 用量日志
```

**数据表**: `ai_conversations`, `system_ai_usage_logs`, `system_operation_logs`

### 3.5 M08 — 质量分析模块

**功能描述**:
拉取仓库代码，调用外部静态分析工具，解析结果并结构化入库。支持评分计算、基线对比和趋势分析。

**支持工具**:

| 工具 | 语言 | 输出格式 | 解析方式 |
|------|------|----------|----------|
| cppcheck | C/C++ | XML | 解析 `<error>` 节点 |
| clang-tidy | C/C++ | stdout/stderr | 正则提取 file/line/rule/severity |
| cpplint | C/C++ | stdout/stderr | 解析行级诊断 |
| flawfinder | C/C++ | stdout/stderr | 解析风险函数命中 |
| pylint | Python | JSON | `--output-format=json` |
| checkstyle | Java | XML | 解析 `<error>` / `<file>` 节点 |

**评分算法**:

```
penalty = Σ(count * weight * tool_weight)
score = max(0, 100 - log(1 + penalty) * 20 / max(1, files_with_issues))
```

**严重性权重**:

| 严重性 | 权重 |
|--------|:----:|
| error | 10.0 |
| warning | 4.0 |
| performance | 3.0 |
| portability | 3.0 |
| style | 0.4 |
| information | 0.1 |

**工具权重**:
- cppcheck / clang-tidy: 1.0（缺陷诊断）
- flawfinder: 0.75（安全启发式）
- pylint: 0.5
- checkstyle: 0.25
- cpplint: 0.08（风格检查，噪声多）

**数据表**: `quality_issues`, `quality_analysis_tasks`, `quality_analysis_runs`, `quality_run_issues`, `quality_baselines`

### 3.6 M09 — 专家识别模块

**功能描述**:
基于 PageRank 算法发现项目的隐形技术专家，支持全局排名和按模块查询。

**算法流程**:
```
1. 从 commits + commit_files 构建开发者协作图
   - 共同修改同一目录 → 建立有向边(权重+=1)
2. 从 pull_requests.raw_json 解析 requested_reviewers → review 关系(权重2.0)
3. PageRank 迭代计算 (damping=0.85, 20次迭代)
   PR(A) = (1-d)/N + d * Σ(PR(T)/L(T))
4. 每个开发者附带统计: commits数、文件数、最近活跃时间、主要负责模块
5. 结果写入 knowledge_chunks(source_type="expert")
```

**接口**:

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/repos/{id}/experts | 全局 PageRank 专家排名 |
| GET | /api/repos/{id}/experts/module | 按模块目录获取专家 |
| POST | /api/repos/{id}/experts/build | 重新计算并写入知识库 |

### 3.8 M12 — 风险检测模块

**功能描述**:
基于仓库历史数据检测异常信号，支持三种检测规则。

**检测规则**:

| 规则 | 描述 | 计算方式 |
|------|------|----------|
| code_churn_spike | 单日代码变更量异常飙升 | 当日 churn vs 前 N 天滚动均值 + 3σ 阈值 |
| issue_backlog_spike | Open Issues 积压突增 | 当日 open 数 vs 过去均值 |
| pr_merge_latency_spike | PR 合并耗时异常上升 | 当日平均耗时 vs 历史均值 |

**数据表**: `risk_alert_runs`, `risk_alert_events`

## 5. 编译与构建

### 5.1 后端编译

```bash
# CMake 配置
cmake -B build -DCMAKE_BUILD_TYPE=Release

# 编译
cmake --build build --config Release
```

**编译依赖**:
- C++17 编译器（MSVC / GCC / Clang）
- SQLite3、OpenSSL、nlohmann-json、cpp-httplib
- vcpkg 包管理器（推荐）

```bash
cd frontend
npm install
npm run build
```
