# 软件需求说明书

## 1. 引言

### 1.1 编写目的
本文档描述「基于 AI 驱动的软件工程一体化度量与协作平台」（DevInsight）的功能需求与非功能需求，为系统设计、开发实现和验收测试提供依据。

### 1.2 项目名称
基于 AI 驱动的软件工程一体化度量与协作平台（DevInsight）

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| RAG | 检索增强生成（Retrieval-Augmented Generation） |
| PageRank | 基于链接分析的排名算法，用于专家识别 |
| Cursor | 增量同步游标，记录上次同步位置 |
| Embedding | 文本向量化表示，用于语义检索 |
| Quality Baseline | 质量基线，定义评分和问题数的阈值 |
| Repo | 仓库（Repository） |

## 2. 总体描述

### 2.1 产品功能
平台提供以下核心功能：

1. **仓库管理**: 注册/删除 GitHub 仓库，管理仓库元信息
2. **数据同步**: 从 GitHub 同步 Issues / PRs / Commits / Releases / CI Runs
3. **度量计算**: 仓库活跃度、健康评分、代码热度分析
4. **质量分析**: 集成多种静态分析工具，提供问题追踪与评分
5. **AI 问答**: 基于 RAG 的工程智能问答，支持全局和单仓库模式
6. **知识库**: 构建工程知识索引（向量+关键词混合检索）
7. **专家识别**: 基于 PageRank 发现隐形技术专家
8. **自动周报**: 聚合数据生成结构化周报
9. **CI 健康**: GitHub Actions 运行监控与趋势分析
10. **风险检测**: 代码变更/Issue 积压/PR 合并延迟异常检测
11. **系统日志**: 平台自身操作日志与 AI 用量统计

### 2.2 用户特征
- **主要用户**: 软件开发团队（技术负责人、架构师、开发者）
- **使用场景**: 
  - 日常查看仓库健康度与质量趋势
  - 通过 AI 问答快速了解项目状况
  - 定期生成周报，识别技术专家
  - 监控代码质量退化与风险

### 2.3 运行环境
- **服务端**: Windows 10+ / Ubuntu 20.04+，建议 4 核 8 GB 以上
- **客户端**: 现代浏览器（Chrome 90+ / Edge 90+ / Firefox 90+）
- **依赖**: cpp-httplib, SQLite3, OpenSSL, nlohmann-json（后端运行时）
- **可选工具**: cppcheck, clang-tidy, cpplint, flawfinder, pylint, checkstyle

## 3. 功能需求

### 3.1 仓库管理

| 功能编号 | FR-01 |
|----------|-------|
| 名称 | 仓库注册 |
| 优先级 | P0 |
| 描述 | 用户输入 GitHub 仓库全名（owner/repo），系统在本地创建仓库记录 |
| 输入 | full_name（string） |
| 输出 | repo_id, full_name |
| 前置条件 | GitHub Token 已配置且仓库存在 |
| 后置条件 | 仓库记录写入 repos 表 |

| 功能编号 | FR-02 |
|----------|-------|
| 名称 | 仓库列表与详情 |
| 优先级 | P0 |
| 描述 | 查看已注册仓库列表及单个仓库的详细信息 |
| 输出 | 仓库 ID、全名、启用状态、介绍文本 |

| 功能编号 | FR-03 |
|----------|-------|
| 名称 | 仓库启用/禁用/删除 |
| 优先级 | P1 |
| 描述 | 用户可启用/禁用仓库（禁用后不同步）、删除仓库（同时清理本地缓存） |

### 3.2 数据同步

| 功能编号 | FR-04 |
|----------|-------|
| 名称 | GitHub 数据同步 |
| 优先级 | P0 |
| 描述 | 从 GitHub 同步仓库数据，支持全量与增量两种模式 |
| 同步内容 | Snapshot（star/fork/watch 快照）、Issues、PRs、Commits、Releases |
| 增量机制 | 基于游标（cursor）记录上次同步位置，下次只拉取新增/变更数据 |

| 功能编号 | FR-05 |
|----------|-------|
| 名称 | Commit 文件同步 |
| 优先级 | P1 |
| 描述 | 遍历本地 commits，逐条拉取 commit 的文件变更信息，用于热点分析 |

### 3.3 度量与健康

| 功能编号 | FR-06 |
|----------|-------|
| 名称 | 仓库度量计算 |
| 优先级 | P0 |
| 描述 | 计算仓库的核心协作指标，包括提交频率、贡献者活跃度、PR 合并率等 |
| 指标项 | commits_last_7d, active_contributors_30d, open_issues, avg_issue_close_days, prs_merged_last_30d, prs_merge_rate, releases_last_90d |

| 功能编号 | FR-07 |
|----------|-------|
| 名称 | 健康评分 |
| 优先级 | P0 |
| 描述 | 基于度量数据计算仓库健康评分（0-100），包含活动性、响应性、质量、发布四个维度 |

| 功能编号 | FR-08 |
|----------|-------|
| 名称 | 热点文件/目录分析 |
| 优先级 | P1 |
| 描述 | 按变更频率统计仓库的热点文件和目录，支持时间窗口和深度配置 |

| 功能编号 | FR-09 |
|----------|-------|
| 名称 | 活跃度趋势 |
| 优先级 | P1 |
| 描述 | 按天聚合 commit 次数，返回时间序列数据，用于趋势折线图展示 |

### 3.4 代码质量分析

| 功能编号 | FR-10 |
|----------|-------|
| 名称 | 静态代码分析 |
| 优先级 | P0 |
| 描述 | 拉取仓库代码分支，调用外部静态分析工具（cppcheck/clang-tidy/pylint/checkstyle 等），解析问题并结构化入库 |
| 支持工具 | cppcheck, clang-tidy, cpplint, flawfinder, pylint, checkstyle |
| 分析模式 | full（全量）/ hot（仅热点目录） |

| 功能编号 | FR-11 |
|----------|-------|
| 名称 | 质量评分 |
| 优先级 | P0 |
| 描述 | 基于分析结果按严重性加权计算质量评分（0-100） |
| 权重 | error: 10.0, warning: 4.0, performance: 3.0, style: 0.4 等 |

| 功能编号 | FR-12 |
|----------|-------|
| 名称 | 质量趋势与排行 |
| 优先级 | P1 |
| 描述 | 跨版本评分趋势、按文件/目录/规则维度的 Top 问题排行 |

| 功能编号 | FR-13 |
|----------|-------|
| 名称 | 质量基线 |
| 优先级 | P1 |
| 描述 | 配置评分/新增问题/错误数的阈值，检测质量退化 |

| 功能编号 | FR-14 |
|----------|-------|
| 名称 | 分析任务管理 |
| 优先级 | P1 |
| 描述 | 创建/查看/运行/删除分析任务，支持手动和定时（weekly/on_release）调度 |

### 3.5 AI 智能问答

| 功能编号 | FR-15 |
|----------|-------|
| 名称 | 知识库构建 |
| 优先级 | P0 |
| 描述 | 从仓库已同步的 Issues / PRs / Commits / Releases 中提取知识块，构建检索索引 |
| 扩展 | 支持代码文件和目录树结构入库 |

| 功能编号 | FR-16 |
|----------|-------|
| 名称 | 知识库检索 |
| 优先级 | P0 |
| 描述 | 关键词检索知识库，返回按相关度排序的知识块，支持单仓库和全局模式 |
| 检索策略 | 混合检索（关键词评分 * 0.4 + 向量相似度 * 0.6） |

| 功能编号 | FR-17 |
|----------|-------|
| 名称 | AI 问答 |
| 优先级 | P0 |
| 描述 | 用户输入问题，系统检索知识库+获取当前指标，调用 LLM 生成带证据引用的回答 |
| 模式 | 单仓库模式（聚焦特定仓库）/ 全局模式（跨仓库检索） |

| 功能编号 | FR-18 |
|----------|-------|
| 名称 | 对话历史 |
| 优先级 | P1 |
| 描述 | 查看历史问答记录，按仓库筛选 |

### 3.6 专家识别

| 功能编号 | FR-19 |
|----------|-------|
| 名称 | 专家发现 |
| 优先级 | P1 |
| 描述 | 基于 PageRank 算法在开发者协作图上迭代计算专家分数 |
| 数据源 | commits（协作图）+ pull_requests（review 关系） |

| 功能编号 | FR-20 |
|----------|-------|
| 名称 | 模块专家 |
| 优先级 | P2 |
| 描述 | 按代码目录查询该模块的专家排名 |

### 3.7 周报生成

| 功能编号 | FR-21 |
|----------|-------|
| 名称 | 自动周报 |
| 优先级 | P1 |
| 描述 | 聚合最近 7 天数据，调用 LLM 生成结构化 Markdown 周报 |
| 内容 | commit/PR/Issue/Release 数量、Top 贡献者、健康评分变化、风险告警 |

### 3.8 CI 健康监控

| 功能编号 | FR-22 |
|----------|-------|
| 名称 | CI 运行数据同步 |
| 优先级 | P1 |
| 描述 | 在仓库同步时自动抓取 GitHub Actions Workflow Runs |

| 功能编号 | FR-23 |
|----------|-------|
| 名称 | CI 健康评估 |
| 优先级 | P1 |
| 描述 | 计算 24h 失败率 + 连续失败次数，给出健康等级（good / warning / critical） |

### 3.9 风险检测

| 功能编号 | FR-24 |
|----------|-------|
| 名称 | 风险扫描 |
| 优先级 | P1 |
| 描述 | 基于历史数据检测异常：代码变更量飙升、Issue 积压突增、PR 合并耗时异常 |
| 告警级别 | info / warning / critical |

### 3.10 系统日志

| 功能编号 | FR-25 |
|----------|-------|
| 名称 | 操作日志 |
| 优先级 | P1 |
| 描述 | 记录平台自身的操作事件（仓库创建、同步、AI 问答等） |
| 字段 | 时间、操作类型、目标、状态、耗时、IP、详情 JSON |

| 功能编号 | FR-26 |
|----------|-------|
| 名称 | AI 用量统计 |
| 优先级 | P1 |
| 描述 | 记录每次 AI 调用的 token 消耗与费用，提供今日统计与查询 |

## 4. 非功能需求

### 4.1 性能需求

| 需求 | 指标 |
|------|------|
| API 响应时间 | < 500ms（不含 LLM 调用） |
| 知识库检索 | < 2s（万级知识块） |
| 质量分析 | < 5 min / 2000 文件（cppcheck） |
| 并发支持 | 10+ 同时请求 |
| 前端页面加载 | < 3s 首屏 |

### 4.2 安全需求
- GitHub Token 仅保存在服务端环境变量/配置文件中
- LLM API Key 不暴露给前端
- 支持 HTTPS 访问
- SQL 注入防护（参数化查询）

### 4.3 可用性需求
- 系统支持 7×24 运行
- 数据库持久化，重启不丢失
- LLM 服务不可用时自动降级

### 4.4 可维护性需求
- 模块化架构，各子系统独立编译
- 完整的更新日志记录
- 配置文件与环境变量分离

### 4.5 可移植性需求
- 后端支持 Windows MSVC 和 Linux GCC/Clang 双平台编译
- 前端为纯静态 SPA，任何 Web 服务器均可托管

## 5. 接口需求

### 5.1 外部接口

| 接口 | 用途 | 协议 |
|------|------|------|
| GitHub REST API | 数据同步 | HTTPS / REST |
| LLM API（OpenAI 兼容） | AI 问答 / 周报生成 | HTTPS / REST |
| Embedding API | 向量生成 | HTTPS / REST |

### 5.2 内部接口

前后端通过 RESTful API 通信，统一返回 JSON 格式，支持分页（limit/offset）、筛选（status/severity/state 等）和排序。

详见 `docs/api_get.md`、`docs/api_post.md`、`docs/api_delete.md` 和 `docs/function.md`。
