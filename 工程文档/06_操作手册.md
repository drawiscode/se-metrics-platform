# 操作手册

## 1. 引言

### 1.1 编写目的
本文档指导用户完成「基于 AI 驱动的软件工程一体化度量与协作平台」（DevInsight）的安装、配置、启动和基本操作。

## 3. 安装指南

### 3.1 从发布包安装（推荐）

#### 步骤 1：获取发布包
从项目的 GitHub Releases 页面下载最新版本的 `se-metrics-platform-vX.X.X.zip`。

#### 步骤 2：解压
```bash
# Windows（解压到目标目录）
# 用文件管理器解压或使用命令：
tar -xf se-metrics-platform-vX.X.X.zip -d D:\se-metrics-platform

# Linux
unzip se-metrics-platform-vX.X.X.zip -d ~/se-metrics-platform
```

#### 步骤 3：配置环境变量
进入 `config/` 目录，将 `config.env.example` 复制为 `config.env`：

```bash
cd se-metrics-platform/config
cp config.env.example config.env
```

编辑 `config.env`，至少配置以下三项：

```env
# ========== 必填项 ==========
# GitHub 个人访问令牌（用于拉取仓库数据）
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx

# 大模型 API 密钥（用于 AI 问答）
LLM_API_KEY=sk-xxxxxxxxxxxxxxxxxxxx

# 向量嵌入 API 密钥（用于语义检索）
EMBEDDING_API_KEY=sk-xxxxxxxxxxxxxxxxxxxx
```

#### 步骤 4：启动服务

**Windows 用户**:
```bash
# 方式一：双击 start.bat
# 方式二：命令行
cd se-metrics-platform
.\devinsight_backend.exe
```

**Linux/Mac 用户**:
```bash
cd se-metrics-platform
chmod +x start.sh
./start.sh
```

启动后终端输出如下:
```
[INFO] 前端静态文件已托管: frontend-dist
DevInsight backend listening on http://127.0.0.1:8080
DB: data/devinsight.db
```

#### 步骤 5：访问平台
打开浏览器，访问 `http://localhost:8080`

### 3.2 从源码构建

#### 后端构建

**前置依赖**:
- Visual Studio 2022（MSVC 编译器）或 GCC/Clang
- CMake 3.20+
- vcpkg 包管理器

**安装第三方库**:
```bash
# 通过 vcpkg 安装
vcpkg install sqlite3:x64-windows openssl:x64-windows nlohmann-json:x64-windows
```

**编译**:
```bash
cd backend

# 配置（注意修改 CMakeLists.txt 中的 vcpkg 路径）
cmake -B build

# 编译
cmake --build build --config Release

# 编译产物位于 build/Release/devinsight_backend.exe
```

#### 前端构建

**前置依赖**: Node.js 20+

```bash
cd frontend
npm install

# 开发模式（热更新，需后端同时运行）
npm run dev

# 生产构建
npm run build
```

## 5. 基本操作

### 5.1 注册仓库

1. 在浏览器中打开 `http://localhost:8080`
2. 在左侧导航栏点击「仓库列表」
3. 在输入框中输入仓库全名（格式：`owner/repo`）
4. 点击「添加仓库」按钮
5. 系统将验证仓库是否存在，成功后显示在列表中

### 5.2 同步数据

1. 在仓库列表中点击目标仓库
2. 进入仓库详情页
3. 点击「同步数据」按钮
4. 选择同步模式（增量/全量）
5. 等待同步完成，页面将显示同步结果

### 5.3 查看质量分析

1. 在仓库详情页中找到「质量分析」面板
2. 点击「运行分析」按钮
3. 选择分析工具（cppcheck / clang-tidy 等）
4. 选择分析模式（全量/热点模式）
5. 设置文件上限
6. 等待分析完成
7. 查看评分、问题列表、严重性分布和趋势图

### 5.4 AI 问答

1. 在左侧导航栏点击「AI 问答」
2. 在输入框中输入问题（支持中文和英文）
3. 可选择指定仓库（默认为全局模式）
4. 点击发送，等待 AI 回答
5. 回答将附带证据引用（知识块来源）

### 5.5 查看系统日志

1. 在左侧导航栏点击「系统日志」
2. 查看顶部统计卡片（今日请求数、错误数、AI 调用次数）
3. 在「操作日志」标签页查看平台操作记录
4. 在「AI 用量」标签页查看 AI 调用消耗
5. 支持按时间范围筛选、按状态筛选、分页翻页
6. 点击「详情」可展开查看完整 JSON 数据

## 6. 常见问题

### Q1: 启动后访问 localhost:8080 显示空白页？
检查 `frontend-dist` 目录是否存在且包含 `index.html`。如果从前端源码构建，先运行 `npm run build`。

### Q2: 同步数据时提示 "GitHub API Error"？
检查 `config/config.env` 中的 `GITHUB_TOKEN` 是否正确配置，以及是否有权限访问该仓库。

### Q3: AI 问答返回空或报错？
1. 检查 `LLM_API_KEY` 和 `LLM_API_BASE` 配置
2. 检查 API Key 是否有余额
3. 如果知识库未构建，先运行「知识库构建」

### Q4: 质量分析没有结果？
1. 检查对应工具是否已安装并配置路径
2. 检查 `QUALITY_ALL_TOOLS` 配置
3. 检查仓库代码是否已同步到本地

### Q5: 如何更新版本？
1. 从 Releases 下载新版本
2. 替换 `devinsight_backend.exe` 和 `frontend-dist/` 目录
3. 保留 `config/config.env` 和 `data/` 目录
4. 重启服务

## 7. 管理维护

### 7.1 日志文件
- 操作日志: 存储在 `system_operation_logs` 表中，可通过「系统日志」页面查看
- 同步运行记录: 存储在 `repo_sync_runs` 表中
- 质量分析运行记录: 存储在 `quality_analysis_runs` 表中

### 7.2 数据备份
数据库文件默认位于 `data/devinsight.db`，定期备份此文件即可。

### 7.3 健康检查
```bash
# 通过 API 检查服务状态
curl http://localhost:8080/api/health
# 返回: {"ok": true}
```
